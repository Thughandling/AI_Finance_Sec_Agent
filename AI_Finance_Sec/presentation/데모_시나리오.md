## 2. 5개 시나리오 · 화면에 떠야 하는 값

각 시나리오는 왼쪽에서 선택 → **`샘플 분석 시작`**. 통화 4문장이 1.25초 간격으로 재생되고,
상단 파이프라인과 우측 패널이 단계별로 갱신된다. 3번째 문장부터 **백그라운드 이상거래 신호**가
활성화된다(통화 맥락과 독립적으로 거래 메타데이터만으로 평가).

### 2-4. 완곡 표현 기관 사칭 (`evasive`) — 기대: 사기 · **의도된 미탐**

> 이 시나리오는 **일부러 넣은 실패 사례**다. 1번과 **같은 수법**(기관 사칭 + 계좌 이동 요구)이지만
> 규칙 어휘("안전계좌", "이체")를 피한 완곡 표현이라 통화 탐지가 실패한다.
> 성공 화면만 보여주지 않기 위해, 그리고 규칙 기반의 한계를 그대로 드러내기 위해 넣었다.

| 항목 | 값 |
|---|---|
| 통화 문장별 위험도 | 8 → 14 → 22 → 28 |
| 최종 통합 위험도 | **30 / 100 · 안전 · 정상** |
| 위험 유형 | 정상 절차 (오분류) |
| 정탐 판정 | 기대 라벨 `사기` ≠ 판정 `정상` → **미탐** ❌ |
| 백그라운드 이상거래 | 합계 **34** · 반영 **30** |
| — 신호 | +12 2배 초과(4,500,000원) / +10 처음 보내는 수취인(TOSS-8821-0455) / +12 통화 중 이체 |
| 경보 전달 계획 | **T2 · 인터스티셜** ← 통화를 놓쳐도 **거래 신호 단독으로 경보 발동** |
| — 채널 | 인앱 인터스티셜 |
| — 억제 채널 | 푸시 알림 (통화 중) |
| 검색 근거 | SAFE-NORMAL-001 (오분류의 결과) |

**1번과 나란히 실행해서 대비를 보여준다:**

| | 1번 검찰 사칭 | 4번 완곡 표현 |
|---|---|---|
| 수법 | 기관 사칭 + 계좌 이동 요구 | **동일** |
| 표현 | "안전계좌로 **이체**하세요" | "잠깐 다른 데로 **옮겨두시면**" |
| 통화 위험도 | 100 (탐지 ✅) | **30 (미탐 ❌)** |
| 백그라운드 이상거래 | 42 → T3 | 34 → **T2 (여전히 경보)** |

**설명 포인트**
1. "같은 공격인데 단어만 바꾸면 규칙은 놓칩니다. 이게 저희 블라인드 평가 Macro F1 40.5%의 실체입니다."
2. "그래서 통화 탐지 하나에 걸지 않았습니다. 통화를 놓쳐도 **거래 신호가 단독으로 T2 경보**를 만듭니다."
3. "이중 트랙은 성능을 자랑하려는 게 아니라, 한쪽이 실패할 것을 전제로 설계한 방어선입니다."

### 2-5. 정상 은행 상담 (`normal`) — 기대: 정상 · Hard Negative

| 항목 | 값 |
|---|---|
| 통화 문장별 위험도 | 7 → 9 → 12 → 10 |
| 최종 통합 위험도 | **18 / 100 · 안전 · 정상** |
| 위험 유형 | 정상 절차 |
| 정탐 판정 | 기대 라벨 `정상` == 판정 → **정탐** (위험 단어가 있어도 오탐 안 함) |
| 백그라운드 이상거래 | 합계 **0** · 반영 **0** — "평소 거래 프로필과 차이 없음" |
| 경보 | **T0 · 무개입** — 채널 없음, 체류 0초 |
| 검색 근거 | SAFE-NORMAL-001 (AI_Finance_Sec 검증셋) 정상 금융상담 확인 기준 |

> **핵심 대비 (3단)**
> - 2-1~2-3 (정탐): 위험도 100 · 이상거래 30 · **T3**
> - 2-4 (미탐): 위험도 30 · 이상거래 34 · **T2** — 통화는 놓쳤지만 거래 신호가 경보를 만든다
> - 2-5 (정상): 위험도 18 · 이상거래 0 · **T0** — 위험 단어가 있어도 개입하지 않는다
>
> 이 3단으로 "잘 잡는다"가 아니라 **"틀릴 때 무엇이 남는가"**를 보여준다.

## 3. 백그라운드 이상거래 탐지를 따로 보여주는 법

심사위원이 "그 신호는 통화 문장에서 뽑은 것 아니냐"고 물으면 다음을 시연한다.

1. **통화와 무관함**: `정상 은행 상담`을 재생한다. 통화 문장에 "대출·수수료·송금" 단어가 나오지만
   이상거래 패널은 **합계 0**이다. 신호는 통화가 아니라 거래 메타데이터(금액·수취인·시간대·통화상태·
   한도상향·분할이체 횟수)에서만 나온다는 뜻.
2. **거래 메타데이터가 좌우함**: `검찰·금감원 사칭`을 재생한다. 같은 통화라도 이 시나리오의 이체는
   9,800,000원(평소 p95 500,000원의 19.6배) · 신규 수취인 · 통화 중 · 한도상향 직후 →
   4개 신호 합계 42, 상한 30 반영.
3. **verdict를 바꾸지 않음**: 이상거래 점수는 **경보 티어만 올리고 사기/정상 판정은 바꾸지 않는다**.
   근거 — `정상 은행 상담`에 이상거래가 있었더라도(가정) 위험도는 통화 기반 18에서 그대로.
   패널 상단 "통합 위험도"와 "백그라운드 이상거래 신호"가 별도 블록인 이유.
4. **상한 30**: 통화 위험도(0~100)에 이상거래는 최대 +30까지만 더해진다. 거래 신호만으로
   과잉 차단하지 않기 위함. 패널에 "합계 42 · 반영 30"으로 명시된다.
5. **로컬 LangGraph 모드**: `설정 > Ollama Local` 선택 후 질문하면, 이 패널 값은 프론트 계산이
   아니라 **FastAPI가 반환한 값**으로 바뀌고 상단에 `session / turn / LLM 호출 예` 메타가 뜬다.
   `graph.py`의 `detect_transaction_anomaly`와 `engine.ts`가 score-for-score 동일함을 회귀
   테스트(`background transaction detector ... stay equivalent across engines`)로 보장한다.

## 4. 챗봇 후속 질문 스크립트

챗봇은 선택된 시나리오 State와 **분리**되어 있다(교차 오염 방지). 따라서 후속 질문은
**맥락을 문장에 담아** 입력한다. 답변은 위험유형별로 달라지고, 근거·검색문서·행동을 함께 제시한다.

| 입력할 질문 | 나오는 답변의 성격 |
|---|---|
| `검찰이라고 전화가 왔는데 계좌가 범죄에 연루됐다며 안전계좌로 이체하래요` | 위험 단계·근거(보호 명목 계좌 이동 요구)·금감원 안내 인용·CTA(통화 종료) |
| `안전계좌가 뭐예요? 그런 게 진짜 있나요?` | "안전계좌·보호계좌·임시보관계좌는 존재하지 않는 표현" + 기관은 계좌 이동을 요구하지 않음 |
| `이 사람이 진짜 검찰인지 어떻게 확인해요?` | 전화로는 신분 확인 불가 → 끊고 공식 대표번호로 직접 확인, 실제 기관은 이 절차를 문제 삼지 않음 |
| `지금 통화 중인데 끊으면 안 된다고 해요` | 통화 중엔 화면이 노출될 수 있음 → 입력·터치 금지, 통화 종료가 최우선 |
| `보안 앱을 설치하라는데요` | 원격제어·비공식 앱 설치 금지, 이미 설치 시 네트워크 차단 |
| `이미 2천만원 송금했어요. 무엇부터 해야 하나요?` | 골든타임 순서: 지급정지 요청 → 1394 → 112 → 증거 보관, "본인이 직접 요청해야 함" 고지 |
| `그럼 저는 어떻게 해야 하나요?` | 순서형 행동 목록(정책 허용목록 내), 위험 시 지급정지·1394 안내 |

모든 답변은 규칙 기반 Safety 검사를 통과한다: 최소 길이, 공식 확인 문구 포함, 위험 시 중단·종료 문구
포함, 외부조치 완료를 사실처럼 주장하지 않음, 한국어 전용, 프롬프트 잔재·코드 블록 없음.

편집 시 API 키 입력값이 프레임에 노출되지 않게 마스킹 유지, 개발자도구 Network 화면은 촬영 금지.

### 5-2. 라이브 심사 워크스루 (약 7분)

1. Mock으로 5개 시나리오 순차 재생, 각 패널 값 위 표대로 설명. **1번 → 4번을 붙여서** 같은 수법·다른 표현의 탐지/미탐 대비를 보여준다 (3분 30초)
2. 백그라운드 이상거래 독립성 시연 — 3절의 1·2번 (1분 30초)
3. 챗봇 후속 질문 3개 (4절에서 골라서) (1분)
4. BYOK로 심사위원이 원하는 Provider·본인 키로 1턴, 폴백 경로 설명 (1분 30초)

## 6. 예상 질의응답

| 질문 | 답변 |
|---|---|
| 위험도 100은 과한 것 아닌가 | 통화 4문장 누적(94) + 이상거래 반영(+30, 상한)으로 100 도달. 문장별 점수(24→45→67→94)를 화면에서 그대로 보여줌. 단일 키워드가 아니라 맥락 조합 점수 |
| 이상거래 신호가 verdict를 못 바꾸면 왜 계산하나 | verdict(사기/정상)는 통화 근거로만 판정하고, 이상거래는 **경보를 얼마나 강하게 줄지**(T0~T3)를 결정. 통화 없이 이체 이상만 있는 경우에도 T1~T2 마찰을 줄 수 있음 |
| RAG가 실제 검색인가 | 폐쇄형 지식베이스(11문서)에서 어휘 매칭 + 위험유형 시맨틱 랭크를 RRF로 융합해 Top3. RAGAS는 실시간이 아니라 배포 전 오프라인 회귀평가로 사용 |
| 왜 통화 중 푸시를 막나 | 보이스피싱범이 피해자에게 화면 공유·원격제어를 시켜 화면을 함께 보는 경우가 많음. 푸시·SMS가 뜨면 범인이 시나리오를 바꿈. 그래서 인앱 인터스티셜·ARS 콜백 등 범인이 못 보는 채널만 사용 |
| Mock과 실제 모델 차이 | Mock은 결정론적 규칙 엔진(같은 입력=같은 출력). BYOK/로컬은 실제 LLM 호출 후 규칙 기반 Safety 검사를 통과해야 노출, 실패 시 Mock 안전응답으로 폴백. 로컬 경로는 Qwen 자유문을 화면에 노출하지 않고 서버 정책 문장만 출력(guarded_policy) |
| 검증 지표 | 내장 검증셋 38건 기준 Macro F1·위험 Recall 화면 표기. 별도 블라인드셋 평가는 `docs/블라인드_40건_평가_방법과_지표_해설.md` |
| 실제 신고·지급정지 되나 | 안 됨. 버튼은 절차 시뮬레이션이고 화면에도 명시. 답변도 "본인이 직접 요청해야 한다"고 고지하며 완료를 사실처럼 말하지 않음 |
