# AI_Finance_Sec 모델 선정 근거

작성일: 2026-08-03  
목표: API 키가 없어도 심사 가능한 MVP와, API 키 입력 시 실제 모델로 확장 가능한 구조

## 1. 최종 선정

| 역할 | 선정 | 이유 |
|---|---|---|
| 기본 데모 | Deterministic Mock Engine | API·과금·네트워크와 무관하게 동일 입력에 동일 결과를 제공해 심사 재현성을 보장한다. |
| 권장 실시간 생성 | `deepseek-v4-flash` | 공식 API가 OpenAI 호환 형식, Tool Call, JSON 출력, 1M 컨텍스트를 지원한다. 반복 데모와 평가 호출에 유리한 비용 구조다. |
| 고신뢰 대안 | `gpt-5.6-terra` | 복잡도와 비용의 균형을 위한 OpenAI 권장 계열이며 Responses API, Tool Calling, 구조화 출력을 사용할 수 있다. |
| 공개모델·금융사 내부망 후보 | `Qwen3.5-35B-A3B` 계열 | Qwen 공식 Agent 생태계가 병렬·다단계·멀티턴 Tool Call을 지원하며 OpenAI 호환 서버로 자체 배포할 수 있다. 실제 도입 시 금융사 GPU·보안 기준에 맞춘 별도 검증이 필요하다. |
| 임베딩 | `BAAI/bge-m3` | 다국어 Dense·Sparse 검색을 한 계열에서 지원해 한국어와 영문 기관자료 혼합 검색에 적합하다. |
| 리랭커 | `BAAI/bge-reranker-v2-m3` | 다국어 Cross-Encoder 방식으로 1차 검색 후보의 문맥 적합도를 다시 계산할 수 있다. |

## 2. 모델 선택 원칙

1. 심사 재현성: API 키가 없어도 핵심 기능이 동작해야 한다.
2. Provider 독립성: 모델 장애·정책·가격 변화가 서비스 전체를 중단시키지 않아야 한다.
3. 한국어 안전 안내: 유창성보다 근거 충실성, 행동 권고 정확성, 과도한 공포 유발 방지가 우선이다.
4. 구조화 출력: 위험도, 근거, 권고 행동, 근거 문서 ID를 JSON으로 받을 수 있어야 한다.
5. Tool Call: 탐지기·RAG·대응정책 Tool을 모델이 제한된 범위에서 호출할 수 있어야 한다.
6. 비용·지연: 위험 안내는 짧아야 하므로 초대형 모델의 긴 추론을 항상 사용하지 않는다.

## 3. 운영 전략

### 3.1 MVP

- 첫 화면 기본값은 `Mock`이다.
- 사용자가 Provider와 API 키를 선택하면 서버 메모리에서 1회 요청에만 사용하고 저장·로그 출력하지 않는다.
- API 오류·시간초과·형식 오류가 발생하면 Mock 안전 응답으로 복귀한다.
- 생성 모델은 위험 점수를 직접 결정하지 않는다. 탐지 점수와 근거는 규칙·통계·분류 계층이 결정한다.

### 3.2 모델 간 교차검증

- 생성 모델과 평가 모델을 가능하면 다른 계열로 둔다.
- 예: DeepSeek 생성 → OpenAI 평가, OpenAI 생성 → DeepSeek 또는 Qwen 평가
- 같은 모델이 자신의 답을 채점할 때 발생할 수 있는 자기선호 편향을 줄인다.
- 최종 합격 기준은 LLM 점수 하나가 아니라 라벨 기반 탐지 지표와 안전 규칙 검사를 함께 사용한다.

## 4. Qwen 사용 판단

Qwen은 P0/P1의 필수 런타임으로 고정하지 않는다. 자체 호스팅은 금융사 내부망·데이터 통제 측면에서 장점이 있지만, MVP 심사 환경에서는 GPU와 서빙 구성이 재현성의 장애가 된다. 따라서 다음 두 경로로 둔다.

- 클라우드 BYOK: 안정적인 Model Studio API 모델 ID를 사용
- P2 내부망: Qwen 공개 가중치를 vLLM 등 OpenAI 호환 서버로 배포 후 한국어 금융 안전 평가를 통과한 버전만 채택

## 5. 제외·보류

- 하나의 Provider에만 종속되는 구현
- 사용자 API 키를 브라우저 저장소·DB·로그에 저장하는 방식
- 생성 LLM이 근거 없이 위험도를 임의 조정하는 방식
- 세 개 이상의 LLM 분석기를 모든 요청에 직렬 호출하는 방식
- 한국어 금융 안전성 검증 없이 공개모델을 운영 기본값으로 지정하는 방식
