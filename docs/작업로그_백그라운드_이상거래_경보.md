## 1. 무엇을 만들었나

통화 맥락과 **독립적으로** 거래를 관찰해 이상 신호를 만들고, 그 신호를 통화 위험도와
합쳐 **경보를 어떻게 전달할지** 결정하는 경로를 추가했다.

| 노드 | 위치 | 역할 |
|---|---|---|
| `transaction_signal_agent` | `backend/app/graph.py` | 평소 거래 프로필 대비 이상 신호 8종 산출 |
| `alert_planner` | `backend/app/graph.py` | 티어·채널·마찰·고객 문구 결정 |
| `detectTransactionAnomaly` / `planAlert` | `app/lib/engine.ts` | 위 둘의 프론트 미러 (score-for-score 동등) |

파이프라인:
`prepare_input → transaction_signal_agent → structured_risk_agent → (knowledge ∥ policy) → ollama_generate → safety_verifier → alert_planner → finalize`

합계는 상한 30으로 잘라 위험 점수에 더한다. 티어 판정에는 상한 전 원점수를 쓴다.

## 2. 왜 이렇게 설계했나

경보가 실패하는 원인은 고객의 부주의가 아니라 **범인의 사전 코칭**이다.
"은행에서 연락 오면 이렇게 답하세요"가 이미 심어져 있으면 경고문은 무력하다.
균일한 팝업은 학습적으로 무시되고, 통화 중 푸시는 오히려 범인에게 화면을 노출시킨다.

그래서 세 가지를 원칙으로 잡았다.

1. **위험도에 비례한 마찰만 준다.** 정상 고객에게는 아무 개입도 하지 않는다(T0).
2. **통화 중에는 푸시·SMS를 억제한다.** 대신 통화를 물리적으로 끊는 ARS 콜백과,
   화면 전환이 없는 은밀 모드를 쓴다.
3. **경고문 대신 증거와 단일 행동을 준다.** 고객 문구는
   `① 무엇이 달랐나 · ② 왜 위험한가 · ③ 지금 할 일 1개` 3블록 고정이며,
   ③은 정책 허용목록 안의 행동 하나만 쓴다. 선택지를 늘리면 결정이 회피된다.

### 지킨 제약

- **거래 이상신호는 `verdict`(정상/사기)를 바꾸지 않는다.** 점수와 등급만 올린다.
  통화 맥락 판정과 평가 지표를 오염시키지 않기 위한 제약이다.
- 단일 CTA와 골든타임 순서는 전부 `POLICY_ACTION_ALLOWLIST` 안에서만 고른다.
- 송금 후 30분 골든타임은 **안내만** 하며 실제 신고·지급정지는 수행하지 않는다.
  `external_action_executed`는 항상 `false`다.
- 거래 컨텍스트가 없으면 기존 판정이 한 글자도 바뀌지 않는다(회귀 방지).

## 4. 그 과정에서 함께 고친 것

### 기존 parity 테스트 실패 (변경 이전부터 존재)

Windows 기본 콘솔 코드페이지(cp949)에서 Python stdout의 한글이 깨져
TS↔Python 비교가 어긋나고 있었다. `PYTHONIOENCODING=utf-8`을 고정해 해결했다.

### 한글 글꼴 미적용

`Geist`는 latin 서브셋만 담아 한글 글리프가 없다. `next/font`가 CSS 변수를
`'Geist', sans-serif`로 만들어, 뒤에 어떤 한글 글꼴을 적어도 제네릭 `sans-serif`가
먼저 매칭돼 도달하지 못했다. `fallback` 옵션으로 한글 글꼴을 `sans-serif` 앞에 넣어 해결.

### Ollama 모드에서 이상거래 신호 패널이 가려짐

Ollama 모드에서는 Safety 패널이 이상거래 패널 자리를 차지해, 백엔드가 계산한 신호를
화면에서 볼 수 없었다. 두 패널을 함께 렌더하도록 바꾸고 회귀 테스트를 걸었다.

## 5. 해결됨 — `npm run start:win` 프로덕션 서버 (2026-09-03)

### 증상

Windows에서 `vinext start`가 **하위 디렉터리의 정적 자산을 전부 404로 응답했다.**
`/og.png` 같은 루트 파일은 200이지만 `/assets/*.js`, `/assets/*.css`, `/data/*.json`이
모두 404가 되어 CSS·JS가 붙지 않았다. 화면이 통째로 깨지고 버튼도 동작하지 않았다.

### 원인 (vinext 0.0.50 Windows 경로 버그)

`node_modules/vinext/dist/server/static-file-cache.js`의 `walkFilesWithStats`가
`path.relative(base, file)` 결과를 그대로 정적 자산 맵의 URL 키로 썼다.

```js
relativePath: path.relative(base, batch[j]),   // Windows: "assets\index.js"
// ...
const pathname = "/" + relativePath;           // "/assets\index.js" 로 색인
```

요청 측(`prod-server.js`)은 이미 `rawPathname.replaceAll("\\","/")`로 정규화해
`/assets/index.js`(슬래시)로 조회하므로 **영원히 매칭되지 않았다.** 구분자가 없는
루트 파일만 우연히 맞았다. 같은 역슬래시 때문에 `.vite/` 스킵, `assets/` 해시자산
판별(`Cache-Control: immutable`), `/index.html` 디렉터리 인덱스 처리도 함께 깨져 있었다.
macOS·Linux에서는 `path.relative`가 슬래시를 반환해 발생하지 않는다.

### 조치

색인 시 경로 구분자를 POSIX 슬래시로 정규화한다. 한 줄이면 위 네 가지가 모두 고쳐진다.

```js
relativePath: path.relative(base, batch[j]).split(path.sep).join("/"),
```

`node_modules` 직접 수정은 재설치 시 사라지므로, 멱등 패치 스크립트
`scripts/patch-vinext.mjs`를 만들고 `package.json`의 `postinstall`에 걸었다.
`start-demo.ps1`도 빌드 전에 한 번 더 실행해 손으로 복원한 `node_modules`를 방어한다.
`patch-package` 같은 새 의존성은 추가하지 않았다(오프라인 설치 안전).

### 검증 (콜드 스타트, 포트 3999)

| 경로 | 이전 | 이후 |
|---|---|---|
| `/` | 200 | 200 |
| `/assets/index-*.js` | **404** | 200 · `application/javascript` · `immutable` |
| `/assets/index-*.css` | **404** | 200 |
| `/data/demo_scenarios.json` | **404** | 200 · 유효 JSON |
| `/favicon.svg` | 200 | 200 |
| `/assets/없는파일.js` | 404 | 404 (정상) |

회귀 테스트 프론트 20/20, 백엔드 40/40 통과.

### 상주 운영

`start-demo.ps1 -Watch` — 기동 후 상주하며 `WatchIntervalSeconds`(기본 20s)마다
Ollama·백엔드·프론트 엔드포인트를 확인하고 죽은 것을 같은 인자로 재기동한다.
로그아웃·재부팅에도 살려면 이 명령을 작업 스케줄러에 등록한다(RUN_WINDOWS.md 5절).
공개 URL 안정화가 필요하면 Quick Tunnel 대신 named tunnel로 전환해야 한다(별도 과제).

> `dev:win` 서버는 IPv6(`[::1]:3000`)에만 바인딩된다. 프로덕션 서버(`start:win`)는
> `0.0.0.0`에 바인딩되므로 `127.0.0.1:3000`·`localhost:3000` 모두 접속된다.
