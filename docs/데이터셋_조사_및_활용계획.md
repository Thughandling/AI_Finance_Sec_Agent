# AI_Finance_Sec 데이터셋 조사 및 활용 계획

작성일: 2026-08-03  
적용 범위: 2026 금융 AI Challenge P0/P1 MVP

## 1. 결론

AI_Finance_Sec의 MVP는 공개된 실제 피해자의 통화·거래 원문을 무리하게 수집하지 않는다. 보이스피싱 영역은 공식기관의 예방 가이드와 공개 사례를 RAG 지식으로 사용하고, 탐지 입력은 개인정보가 없는 합성 시나리오로 구성한다. 이상거래 영역은 공개 합성·익명 데이터로 탐지 로직과 시각화를 검증하고, 실제 금융사 FDS 데이터는 P2의 교체 가능한 데이터 어댑터로 남긴다.

이 방식은 데모 재현성, 개인정보 비수집, 데이터 출처 설명 가능성을 동시에 확보한다.

## 3. MVP 데이터 구성

### 3.1 통화·문자 시나리오

- 위험 시나리오: 기관사칭, 대출빙자, 가족빙자, 악성 앱 설치, 개인정보 탈취, 투자·리딩방, 택배·부고 스미싱
- 정상 시나리오: 은행의 일반 상품 안내, 가족의 정상 송금 요청, 본인이 시작한 인증 절차, 일반 대출 상담
- Hard Negative: `검찰`, `송금`, `대출`, `앱 설치` 같은 단어가 등장하지만 사기가 아닌 문장
- 각 샘플 필드: `scenario_id`, `label`, `risk_type`, `utterance`, `expected_signals`, `expected_level`, `recommended_actions`, `source_basis`

### 3.2 거래 시나리오

- 금액 급증: 사용자 기준선 대비 고액 이체
- 속도 이상: 짧은 시간에 다수 계좌로 연속 이체
- 신규 수취인: 첫 거래 계좌로 고액 이체
- 시간 이상: 평소 사용하지 않는 심야 시간
- 기기·지역 변화: 신규 기기와 비정상 지역의 결합
- 통화 결합 위험: 의심 통화 직후 송금 시도
- 각 샘플 필드: `transaction_id`, `timestamp`, `amount`, `recipient_age_days`, `device_status`, `location_delta`, `velocity_10m`, `call_risk_score`, `label`, `expected_reasons`

## 4. 분할 및 품질관리

- 동일 시나리오의 문장 변형이 학습·평가 양쪽에 섞이지 않도록 `scenario_family` 단위로 분할한다.
- 실제 시간 순서를 모사해 과거 데이터로 기준선을 만들고 미래 구간으로 평가한다.
- 위험과 정상의 비율을 실제 환경처럼 불균형하게 둔 평가셋과, 기능 시연용 균형셋을 분리한다.
- 이름, 전화번호, 계좌번호, 주민번호, 실제 피해자의 음성은 수집·저장하지 않는다.
- 합성 데이터는 화면과 문서에 `데모용 합성 데이터`라고 표시한다.

## 5. 평가 지표

정확도 하나만 사용하지 않는다.

- 탐지: Precision, Recall, F1, Macro F1, PR-AUC
- 운영 위험: False Positive Rate, False Negative Rate
- 임계값: 위험 누락 비용이 크므로 Recall을 우선하되, 사용자 피로를 막기 위해 FPR 상한을 함께 둔다.
- 설명: 탐지 사유가 기대 근거와 일치하는 비율
- 대응: 권고 행동이 상황별 정답 집합에 포함되는 비율
