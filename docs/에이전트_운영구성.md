## 현행 구성 — Claude Code 서브에이전트

정의 파일은 `.claude/agents/`에 있으며 저장소와 함께 형상관리된다. 세션에서 이름으로 호출하거나, `description`에 적힌 조건에 해당하면 메인이 위임한다.

| 에이전트 | 모델 | 도구 | 역할 | 호출 시점 |
|---|---|---|---|---|
| `eval-blind` | Opus | Read·Write·Edit·Grep·Glob·PowerShell | 기존 평가셋과 겹치지 않는 신규 블라인드셋 생성·측정·동결 | 탐지 로직 변경 후, 제출 전 |
| `parity-guard` | Sonnet | Read·Grep·Glob·PowerShell | TS↔Python 동등성 검증, 회귀 테스트, 변경 순서 점검 | `engine.ts`·`graph.py` 판정 로직 수정 직후 |
| `safety-critic` | Opus | Read·Grep·Glob | 안전 경계 적대적 검토 (읽기 전용) | 생성·정책·Safety 경로 변경 시, 시연·제출 전 |
| `doc-sync` | Sonnet | Read·Grep·Glob | 코드↔문서 정합 감사, 과장 표현 검사 (읽기 전용) | 코드 변경 후, 제출 전 |
| `repo-keeper` | Sonnet | Read·Grep·Glob·PowerShell | 시크릿·혼입 차단, `.gitignore`·대장·브랜치 점검 | 커밋·푸시 전, 파일 추가·삭제 시 |

### 운영 원칙

- **서브에이전트는 소스와 문서를 수정하지 않는다.** 보고서만 반환하고 메인이 반영한다. 파일 소유권 충돌을 막기 위한 규칙이며 아래 Codex 시절부터 이어진다.
- 유일한 예외는 `eval-blind`가 자기 평가 데이터셋과 리포트를 쓰는 것이다. "평가 직후 즉시 동결" 규칙이 이를 요구한다.
- `parity-guard`는 불일치에서 **어느 쪽이 옳은지 판정하지 않는다.** 양쪽 값을 제시하고 메인이 결정한다.
- 각 에이전트는 별도 컨텍스트에서 실행되므로 도구 출력이 메인 대화를 오염시키지 않는다. 반대로 메인의 최근 맥락도 자동으로 전달되지 않으니, 호출할 때 필요한 배경을 프롬프트에 담아야 한다.

## 이력 — Codex 서브에이전트 구성

아래는 Claude Code로 전환하기 전 Codex에서 운영하던 4역할 구성이다. 현행 구성의 설계 근거로 남긴다.

### 확인 경로

이 절은 프로젝트 작업 에이전트의 역할과 최근 확인 상태를 사용자가 직접 확인하기 위한 운영 대장이었다.

- 메인: `/root`
- 개발·형상관리: `/root/development_git`
- 비판·리스크 리뷰: `/root/architecture_review`
- 검증·QA: `/root/verification_qa`

## 현재 상태

| 에이전트 | 역할 | 최근 상태 |
|---|---|---|
| `/root` | 사용자 협의, 설계, 분배, 통합, 최종 보고 | 운영 중 |
| `/root/development_git` | 승인된 구현, 테스트, 로컬 Git commit | Qwen P1 개발 완료·commit `50884b6` |
| `/root/architecture_review` | 읽기 전용 비판·리스크 검토 | P0/P1 최종 승인·차단 없음 |
| `/root/verification_qa` | 독립 검증·QA·출시 판단 | P0/P1 최종 GO |

## UI 표시 방식

위 에이전트들은 현재 Codex 작업 내부에서 동작하는 서브에이전트이므로 사이드바에 별도 작업으로 표시되지 않는다. 사이드바에는 사용자가 직접 열고 대화하는 독립 Codex 작업만 표시된다.

서브에이전트의 실시간 상태는 메인이 내부 에이전트 목록을 조회해 이 문서 또는 채팅으로 보고한다. 이 파일은 자동 갱신되는 모니터가 아니며, 중요한 작업 배정·완료 시 메인이 갱신한다.

## 운영 원칙

- 사용자는 메인 작업에서 지시한다.
- 메인이 각 서브에이전트에 구체적인 범위와 완료 기준을 전달한다.
- 서브에이전트 결과는 메인에게 반환된다.
- 메인이 충돌과 품질을 조정해 사용자에게 통합 결과를 보고한다.
- 사이드바에서 각 역할과 직접 대화해야 한다면 서브에이전트가 아니라 별도의 사용자 소유 Codex 작업 세 개를 생성해야 한다.
