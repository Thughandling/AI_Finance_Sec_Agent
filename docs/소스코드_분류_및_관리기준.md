# AI_Finance_Sec 소스코드 분류 및 관리 기준

최종 갱신일: 2026-08-16

## 1. 재분류 원칙

- 실행 경로와 배포 설정이 깨지지 않도록 파일을 물리적으로 이동하지 않고 **역할·권위·관리 상태 기준으로 논리 재분류**한다.
- 실제 서비스 동작을 결정하는 실행 코드를 단일 기준 소스(SSOT)로 지정한다.
- Notebook, 샘플, 생성 결과물은 실행 기준 소스와 구분한다.
- 사용 여부가 확인되지 않은 파일은 즉시 삭제하지 않고 `보관 검토`로 표시한다.

## 2. 핵심 소스 분류

| 분류 | 기준 파일 | 역할 | 관리 원칙 |
|---|---|---|---|
| Python 판정·오케스트레이션 | `AI_Finance_Sec/backend/app/graph.py` | State, Node, Edge, Qwen 구조화 판정, 규칙 결합, RAG, 정책, Safety, Memory | **최상위 기준 소스** |
| FastAPI 진입점 | `AI_Finance_Sec/backend/main.py` | `/api/chat`, `/health` API 및 요청·응답 스키마 | graph 변경과 함께 검증 |
| Cloud BYOK 라우터 | `AI_Finance_Sec/app/api/chat/route.ts` | OpenAI·Claude·Gemini·DeepSeek·Qwen Cloud 호출 | API 키 비저장 원칙 유지 |
| 브라우저 Mock 엔진 | `AI_Finance_Sec/app/lib/engine.ts` | API 없이 동작하는 데모 판정·검색·안전응답 | Python 코어와 회귀 parity 유지 |
| 화면 | `AI_Finance_Sec/app/page.tsx` | 모델 선택, 시나리오, 채팅, 판정·근거 표시 | UI 변경 시 렌더링 테스트 수행 |

## 3. 지원·검증·배포 분류

### 지원 소스

- `app/layout.tsx`, `app/globals.css`, `app/chatgpt-auth.ts`: 화면·메타데이터·인증 보조
- `backend/requirements.txt`, `package.json`: 실행 의존성과 명령 정의

### 평가·검증 자산

- `public/data/evaluation_cases.json`: 기본 회귀셋
- `public/data/evaluation_holdout.json`: 고정 홀드아웃
- `public/data/evaluation_adversarial_round2.json`: 2차 공격·경계 케이스
- `public/data/evaluation_adversarial_round3.json`: 3차 공격·경계·멀티턴 케이스
- `tests/engine.test.mjs`, `backend/tests/test_api.py`: TypeScript·Python 동등성, 분류·RAG·안전성 자동 검증
- `backend/scripts/smoke_ollama.py`, `backend/smoke/*`: Ollama 실호출 점검과 증적

### 빌드·배포 지원

- `.openai/hosting.json`, `vite.config.ts`, `build/sites-vite-plugin.ts`, `worker/index.ts`: 현재 Sites/Cloudflare 빌드 경로와 연결되므로 임의 이동·삭제 금지
- `db/*`, `drizzle.config.ts`, `drizzle/meta/*`, `examples/d1/*`: 현재 핵심 서비스에서는 직접 사용하지 않지만 배포 템플릿·향후 영속화 후보이므로 `보관 검토`로 유지

## 4. Notebook 관리 정책

`AI_Finance_Sec_Chatbot_Orchestration.ipynb`는 현재 `backend/app/graph.py`를 가져다 쓰지 않는 독립 프로토타입이다. 최신 구조화 Qwen 판정, conservative fusion, incident state, 현재 RAG·Safety 구현과 완전히 일치하지 않으므로 다음과 같이 관리한다.

- 권위 수준: `설명·실험용 프로토타입`
- 관리 상태: `동기화 필요`
- 제출·배포 기준 코드로 인용하지 않는다.
- 후속 정리 시 Notebook은 `backend.app.graph`를 import하여 실행·설명만 담당하도록 얇게 만든다.

## 6. 변경 시 동기화 규칙

1. 위험 판정 변경: `backend/app/graph.py` → `app/lib/engine.ts` → 양쪽 테스트 → 평가 JSON 순으로 함께 반영한다.
2. API 응답 변경: `backend/main.py`, `app/api/chat/route.ts`, `app/page.tsx`를 함께 검토한다.
3. 피해 대응 문구 변경: 정책 응답, Safety 검사, 1394·112·금융회사 지급정지 요청 테스트를 동시에 수정한다.
4. Notebook은 구현 안정화 이후 설명용으로 동기화하며, 실행 기준으로 사용하지 않는다.
5. 생성물(PDF, PPTX, HWPX, smoke JSON)은 원본 소스와 분리하고 생성일·기준 커밋을 기록한다.

## 7. 형상관리 기준

- API 키·토큰·개인정보·로컬 모델 파일은 Git에 저장하지 않는다.
- `.venv`, `node_modules`, `.next`, 캐시, 임시 렌더 파일은 관리 대장에서 제외한다.
- 제출 문서는 `통합수정본 → 제출본` 반영 관계와 최종 검증일을 대장 비고에 기록한다.
- 삭제·이동은 대장의 `보관 검토` 항목을 확인하고 빌드·테스트 통과 후 별도 커밋으로 수행한다.
